# 写完成报告

## 概述

计划执行完成后，**完成报告必须写入文档文件**，不能只停留在对话里。对话给摘要，文档存完整报告。

## 何时使用

- executing-plans / subagent-driven-development 的所有任务完成、验证通过、进入收尾时（对应 executing-plans 步骤 4）
- 用户要求"写完成报告 / 执行报告 / 交付总结"时

不适用：计划还在执行中、任务未全部验证通过时。

## 核心模式

1. 收集事实：计划文件路径（`docs/superpowers/plans/*.md`）、当前分支、各任务完成情况、每个验证命令的量化结果、任何偏离计划之处
2. 用下方模板将完整报告写入 `docs/superpowers/reports/YYYY-MM-DD-<topic>-report.md`
3. 对话中只给摘要 + 文档链接（用 `file:///` 引用）
4. 将报告文档与相关改动一起 commit（遵循项目 commit 风格）

## 完成报告文档模板

```markdown
# <功能/计划名> 执行报告

**计划：** docs/superpowers/plans/<文件名>.md
**分支：** <branch>
**任务：** N/N 已完成

### 完成的任务
1. ✅ <任务一>
2. ✅ <任务二>

### 验证结果
- <命令 1>：<量化结果>
- <命令 2>：<量化结果>

### 偏离计划的地方
- <偏离项，无则写"无">

### 下一步
<后续动作，或按 finishing-a-development-branch 处理合并/PR>
```

## 常见错误

| 借口 | 现实 |
|------|------|
| "在对话里报告就够了" | 对话不持久化，之后没人能看到。必须写文档。 |
| "结果已验证，不用写数字" | 报告必须含具体命令和量化结果（如"134MB → 102MB，-24%"）。 |
| "没有偏离计划，不用写这节" | 也写"无"——明确说明，避免读者猜测。 |
| "报告内容和计划重复，写个摘要就行" | 报告聚焦"做完了什么、验证了什么、结果如何"，与计划互补。 |
| "这个计划很小，不值得写报告" | 越小的计划越容易被人遗忘，报告只需几分钟。无例外。 |
| "用户说对话里汇报就行" | 用户说的是汇报形式，不代表不要持久化文档。两者都给。 |

## 红线

- 只对话汇报、不写文档文件 = 没有完成报告
- "验证通过"但无命令、无数字 = 未验证
- 跳过"偏离计划"一节 = 报告不完整
- 因计划"太小"或"用户只要对话"而不写文档 = 违规
